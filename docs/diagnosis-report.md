# 마이그레이션 진단 보고서 (초안)

> 이 문서는 2단계에서 의뢰인용 보고서로 완성한다. 지금은 1단계에서 레거시 샘플에 **의도적으로 넣은 문제와 그 위치**를 기록한 내부 메모다.
> 레거시 코드에는 정답을 드러내는 주석을 달지 않았으므로, 이 목록이 유일한 정답지다.

## 대상 프로그램 개요

| 항목 | 내용 |
|---|---|
| 이름 | 생산실적관리 v1.3 (`ProdMgr.exe`) |
| 기술 스택 | .NET Framework 4.8, WinForms, System.Data.SQLite 1.0.119, INI 설정 (x86) |
| 화면 | 메인(작업지시 목록·등록·수정·삭제), 실적 입력, 일별 리포트 — 3개 |
| 소스 | `legacy/LegacyRescue.Legacy.WinForms/` |

참고: 이 샘플은 Linux에서도 컴파일을 확인할 수 있게 SDK 스타일 csproj를 쓴다. 실제 현장의 같은 시기 프로젝트는 보통 구형 csproj + `packages.config`이며, 이전 작업의 첫 단계로 SDK 스타일 전환이 필요하다.

## 내부 메모: 의도적으로 넣은 문제 목록

### 1. 보안 — SQL 문자열 조립

| 위치 | 내용 |
|---|---|
| `MainForm.LoadList` | 조회 조건(날짜, 라인)을 문자열로 조립. 행마다 품목명 조회도 조립 |
| `MainForm.btnSave_Click` | INSERT / UPDATE에 `txtRemark.Text`를 그대로 연결 → 비고에 `'`를 넣으면 저장 실패, SQL 인젝션 가능 |
| `MainForm.btnDelete_Click`, `ResultForm.btnDelete_Click` | DELETE 조립 (값은 정수라 인젝션은 어렵지만 일관성 없음) |
| `ReportForm.LoadReport` | 날짜 조건 조립 3곳 |
| `ResultForm.btnSave_Click` | **여기만 파라미터 사용** — 나중에 다른 사람이 고친 흔적. 한 파일 안에서도 방식이 섞여 있음 |

### 2. 구조 — 거대 Form, 로직 혼재

- 모든 DB 접근·계산·화면 갱신이 Form 이벤트 핸들러 안에 있다. 계산 규칙(달성률·불량률·가동률)이 `MainForm`과 `ReportForm`에 **중복** 구현되어 있다.
- 연결 문자열·DB 경로·라인 목록을 전역 `static` 클래스 `G`가 들고 있다.
- `SQLiteConnection` / `SQLiteDataReader`를 `using` 없이 열고 닫는다. 예외가 나면 연결이 누수되고 DB 파일 잠금이 남는다.
- 화면 데이터가 전부 문자열 `DataTable`이고 컬럼명이 한국어다. 타입이 없어 숫자 계산을 할 때마다 다시 파싱한다.

### 3. 안정성·성능 — UI 스레드 동기 조회와 N+1

- `MainForm.LoadList`: 작업지시 1건마다 품목명 쿼리 1회, 실적 합계 쿼리 1회 → 지시 N건이면 쿼리가 2N+1회. 모두 UI 스레드에서 동기로 실행된다.
- `ProductionResult.WorkOrderId`에 인덱스가 없어, 실적이 쌓일수록 합계 쿼리가 전체 스캔이 된다.
- 결과적으로 기간을 넓혀 조회하면 화면이 "응답 없음"이 된다. 대량 데이터 재현은 6단계(`DbTool gen-bulk`)에서 측정한다.
- 작업지시를 삭제해도 그 실적은 지워지지 않는다(고아 실적). FK도 없다.
- 지시번호는 `COUNT(*) + 1`로 매긴다. 중간 지시를 삭제한 뒤 새로 등록하면 번호가 중복될 수 있다.

### 4. 호환성 — HiDPI, 인코딩, 경로

- `AutoScaleMode`가 화면마다 다르다: `MainForm` = Font, `ResultForm` = None, `ReportForm` = Dpi. DPI 인식 매니페스트(`app.manifest`)도 없다. 150% 배율에서 `ResultForm`만 흐릿하고 작게 보이는 등 화면마다 다르게 깨진다.
- 모든 컨트롤이 고정 픽셀 좌표·크기이고 Anchor/Dock이 없다. 창을 키워도 그리드가 늘어나지 않는다.
- 폰트를 `굴림`으로 고정했다.
- INI를 `GetPrivateProfileString`(ANSI API)으로 읽는다 → INI 파일이 CP949여야 한다.
- CSV를 `Encoding.Default`로 저장한다 → 한국어 Windows에서는 CP949라서 엑셀에서 잘 열리지만, 영문 Windows나 "UTF-8 베타 옵션"을 켠 PC에서는 한글이 깨진다.
- CSV에 이스케이프가 없다 → 비고에 쉼표가 있으면 열이 밀린다.
- 경로를 하드코딩했다: `C:\ProdMgr\ProdMgr.ini`, `C:\ProdMgr\data\prodmgr.db`, `C:\ProdMgr\export\`. INI가 없을 때만 exe 폴더를 쓴다.
- x86 전용 빌드(`SQLite.Interop.dll` x86).

### 5. 계산 특이점 (의사결정 항목)

특성화 테스트가 이 두 가지를 그대로 고정한다. 2단계 보고서에서 "유지할지 수정할지"를 의뢰인 결정 항목으로 제시한다.

#### 특이점 A — 은행가 반올림

- 위치: `MainForm.LoadList`(작업지시별 달성률·불량률), `ReportForm.LoadReport`(라인·교대별, 합계)
- 원인: `Math.Round(x, 1)`의 기본 모드는 `MidpointRounding.ToEven`이다.
- 증상: 95.25% → **95.2**(일반적인 사사오입이면 95.3), 1.25% → **1.2**(1.3).
- 시드에 넣은 재현 사례:
  - 2026-09-03 L2 주간: 381/400 = 95.25%
  - 2026-09-07 L2 야간: 불량 1/80 = 1.25% (작업지시 목록에서 보임)
- 영향: 표시값이 0.1%p 다를 뿐 집계 결과는 바뀌지 않는다. 하지만 엑셀로 다시 계산한 값과 다르다는 민원이 나올 수 있다.

#### 특이점 B — 야간 교대 날짜 경계

- 위치: `ReportForm.LoadReport`. 실적을 `WorkOrder.WorkDate`가 아니라 **`ProductionResult.EnteredAt`의 날짜**로 모은다. 계획 수량은 `WorkDate`로 모은다.
- 결과: 야간 교대 중 자정 이후에 입력된 실적이 **다음 날** 리포트의 야간 행에 합산된다. 분자(실적)와 분모(계획)의 날짜 기준이 서로 다르다.
- 증상(시드 DB 기준):
  - 2026-09-02 L3 야간 달성률 **175.2%**. 작업일 기준으로 계산하면 93.7%.
  - 2026-09-01 L1 야간은 실적 0. 해당 실적이 9/2 리포트로 넘어갔기 때문이다.
  - 일요일(9/27) 리포트에 계획 0, 양품 961 같은 행이 나온다. 9/26 토요일 야간 실적이 넘어온 것이다.
  - 8/31 야간 실적은 9/1 리포트에, 9/30 야간 실적은 10/1 리포트에 잡힌다. 월간 집계 기간도 하루씩 밀린다.
- 현장에서 오래 방치된 이유(설정): 며칠치를 합치면 양품 총량은 맞고, 주간 행은 정확하다. "야간 달성률은 원래 들쭉날쭉하다"로 넘어갔다.
- 수정안: 실적을 `WorkDate` 기준으로 모으고, 교대 시간 정보로 작업 시각을 검증한다. 과거 리포트 수치가 바뀌므로 의뢰인 결정이 필요하다.

#### 참고 — 특이점은 아니지만 정의를 확인할 항목

- 계획 수량이 0이면 달성률을 `0.0`으로 표시한다(예: 9/9 L1 주간 "샘플 생산"). "-"로 표시할지 결정이 필요하다.
- 가동률 = 작업시간 합계 / 교대 시간(INI, 휴식 미차감). 하나의 행에 여러 날 실적이 섞이면(특이점 B) 100%를 넘을 수 있다.

## 특성화 테스트용 출력 지점

`GoldenExport.cs` + `Program.Main`의 `--export-golden <db> <outdir>` 분기. 레거시 원래 기능 외에 유일하게 추가한 코드다.

- 기존 `ReportForm.LoadReport` / `ExportCsv`, `MainForm.LoadList` / `SaveListCsv`를 **화면 없이 그대로 호출**한다. 계산 코드는 한 줄도 바꾸지 않는다.
- 출력:
  - `daily/yyyy-MM-dd.csv`: 시드 기간 전체 날짜(2026-08-31 ~ 2026-10-01)
  - `workorders.csv`: 전체 작업지시 목록
- 출력 바이트는 사용자가 버튼으로 받는 CSV와 같다(CP949, CRLF).
- 현장 적용 시의 의미: 레거시 코드를 리팩터링하지 않고 "관찰 지점"만 최소로 추가해야 기준값 자체를 믿을 수 있다.
