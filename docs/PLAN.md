# LegacyRescue 작업 계획

목표: 약 2주 안에 레거시 샘플(Before) → 진단 보고서 → 특성화 테스트 → .NET 8 WPF(After) → 전후 비교까지 완성해 포트폴리오로 공개한다.

진행하면서 체크박스를 갱신한다. 작업 위치는 `CLAUDE.md`의 "작업 환경 분담"을 따른다.

- **[클라우드]** Linux 클라우드 세션에서 구현·테스트 가능
- **[로컬]** Windows 로컬 세션에서 실행 검증 필요

---

## 0단계 — 환경 준비 (0.5일)

- [x] `.gitignore`, `README.md` 초안 (초기 커밋에 포함)
- [ ] [클라우드] `legacy/`, `modern/` 솔루션 골격 생성 (`CLAUDE.md` 구조와 대상 프레임워크대로)
- [ ] [클라우드] `Directory.Build.props` (nullable, 경고 수준 — 단, legacy 폴더는 레거시 스타일 유지를 위해 별도 설정)
- [ ] [클라우드] `data/schema.sql`, `data/seed.sql` — 3개 라인, 2개 교대, 약 30일치 작업지시·실적 (가상 품목명)
- [ ] [클라우드] 시드 스크립트로 SQLite DB를 만드는 도구 또는 스크립트

**완료 기준**: 두 솔루션 빌드 성공, 시드 DB 생성 확인

## 1단계 — 레거시 샘플 제작 (2일)

`CLAUDE.md`의 "레거시 샘플 작성 규칙"을 따른다.

- [ ] [클라우드] 메인 Form: 작업지시 목록·등록·수정·삭제
- [ ] [클라우드] 실적 입력 Form
- [ ] [클라우드] 일별 리포트 Form (라인·교대별 달성률, 불량률, 가동률, 합계)
- [ ] [클라우드] CSV 내보내기
- [ ] [클라우드] INI 설정 (DB 경로, 라인 목록, 교대 시간)
- [ ] [클라우드] 의도한 문제점과 계산 특이점 1~2개 반영 (목록은 `docs/diagnosis-report.md` 초안에만 기록)
- [ ] [클라우드] 숨김 옵션 `--export-golden <db> <outdir>` — 리포트·CSV 결과를 파일로 출력
- [ ] [로컬] 실행 확인, 화면 캡처(Before), HiDPI 깨짐 캡처

**완료 기준**: 레거시 앱이 Windows에서 정상 동작하고 의도한 문제가 재현됨

## 2단계 — 마이그레이션 진단 보고서 (1일)

크몽 입문 상품 "레거시 프로그램 진단 보고서"의 견본이 된다. 의뢰인이 읽을 수 있는 수준으로 쓴다.

- [ ] [클라우드] `docs/diagnosis-report.md` 작성
    - 현황 요약 (기술 스택, 규모: 파일 수·코드 줄 수, 화면 수)
    - 구조 분석 (의존성, 결합도, 계산 로직 위치)
    - 위험 요소 (보안: SQL 조립, 안정성: UI 멈춤, 호환성: HiDPI·OS, 유지보수성)
    - 발견된 계산 특이점과 의사결정 필요 항목 (유지 vs 수정)
    - 이전 전략 비교: 전면 재작성 vs 점진 이전(Strangler), 선택 근거
    - 단계별 공수 산정과 일정
- [ ] [로컬] PDF로 변환 (포트폴리오 첨부용)

**완료 기준**: 비개발자 의뢰인이 읽고 의사결정할 수 있는 보고서

## 3단계 — 특성화 테스트 (1.5일)

- [ ] [로컬] 레거시 앱으로 `data/golden/` 기준 파일 생성
- [ ] [클라우드] `LegacyRescue.Characterization` 프로젝트: 시드 DB → 신규 로직 실행 → 골든 파일 비교 (수치는 소수점 규칙까지 정확히 비교)
- [ ] [클라우드] 비교 실패 시 차이를 읽기 쉽게 출력하는 헬퍼
- [ ] [클라우드] (이 시점에는 신규 로직이 없으므로) 테스트 골격과 골든 파일 파서까지 완성, 대상 구현은 4단계에서 연결

**완료 기준**: 골든 파일 커밋, 테스트 하네스 동작

## 4단계 — 로직 분리 (2일)

- [ ] [클라우드] Domain: 작업지시, 실적, 교대, 리포트 계산 규칙 (레거시와 동일 결과, 특이점 포함)
- [ ] [클라우드] Infrastructure: 레거시와 같은 스키마를 읽는 SQLite 저장소 (Dapper, 파라미터화 쿼리)
- [ ] [클라우드] Application: 리포트 생성, CSV 내보내기 서비스
- [ ] [클라우드] 특성화 테스트를 신규 로직에 연결 → 전부 통과
- [ ] [클라우드] 단위 테스트 (경계값: 야간 교대 날짜 경계, 0 나누기, 반올림)

**완료 기준**: 특성화 테스트 100% 통과 (Linux에서 실행)

**완료 기준**: 레거시의 모든 기능이 신규 앱에서 동작

## 7단계 — C++ 계산 DLL 재사용 (선택, 1.5일)

"핵심 C++ 로직은 살리고 UI만 현대화"하는 점진 이전 시나리오.

- [ ] [로컬] `Legacy.Calc`: 가동률·불량률 계산을 C API로 노출하는 C++ DLL (레거시 WinForms도 이 DLL을 호출하도록 변경)
- [ ] [클라우드] `LegacyRescue.Native`: P/Invoke 래퍼 (`LibraryImport`, 구조체 마샬링, 오류 코드 처리)
- [ ] [로컬] 신규 앱에서 C# 구현과 DLL 구현을 설정으로 전환, 특성화 테스트 양쪽 통과
- [ ] [클라우드] 진단 보고서에 "재작성 vs 재사용" 비교 추가

**완료 기준**: 같은 골든 파일로 C# 구현·DLL 구현 모두 통과
